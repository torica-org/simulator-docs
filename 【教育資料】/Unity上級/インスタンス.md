# インスタンス

インスタンスとは，`class`の処理を実際におこなう実体です．  
そもそも`class`が，処理のテンプレート（語弊を生みそうだが）のようなもので，それ自体が実際に実行されるわけではありません．

`MonoBehavior`が継承されているC#スクリプトの場合，GameObjectにアタッチすることでインスタンスになります（多分）．

`MonoBehavior`が継承されていないC#スクリプトの場合，以下のように自身でインスタンス化する必要があります．

## インスタンスの作成（インスタンス化：実体化）
インスタンスを作成するには，`class`のコンストラクタを呼び出します．
```cs
var instance = new();
```
`class`に独自のコンストラクタを書けば，インスタンス化と同時に独自の初期化処理を走らせることができます．

## インスタンスの使用
インスタンス化してようやく，インスタンスのメソッドやプロパティにアクセスできます（やっと「使える」ようになります）．  
どこまでアクセスさせるかは，アクセス指定子（`public`や`private`など）で指定できます．
```cs
instance.Method();
Debug.Log(instance.Property);
```

## 複数のインスタンス
`class`はテンプレートのようなものといいましたが，それ故にいくつもクローンを作ることができます．
```csharp
public AerodynamicCalculator calc1;
public AerodynamicCalculator calc2;

private void Start()
{
    calc1 = new();
    calc2 = new(); // 2台目の飛行機を同時にシミュレーションすることも可能
}
```
では`MonoBehaviour`が継承されているスクリプトは複数作れないのか？
`Prefab`（プレハブ）という仕組みを使えば，`Instatiate()`関数（`using UnityEngine`が必要）でアタッチした`GameObject`ごと複数生成できます．
