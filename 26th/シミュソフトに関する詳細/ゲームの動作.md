# ゲームの動作

### シミュレーションの開始・停止について
- プラホ待機中（Preparation）は、`Time.timeScale = 0.0f;`により、時間が経過する速度がゼロ、すなわち時間が止まっている（※このことは様々な不都合を生み出すため、変更してもいいかもしれない）
- `GameParameter.Status.Flight`に変更されると、`GameManager`が`Time.timeScale = 1.0f;`を設定し、動き出す

## 起動時
- ゲーム起動時、シーンは複数回ロードされている（`Config.cs`の弊害だと思われる、`Config.txt`の監視を遅らせるなど、調整すべき）

### StartMethod
25thで処理をまとめるために作られた．

以下の`class`のメソッドが呼び出される．
- `ChangeAircraft`：`Config.txt`と`AircraftData`を実装してから未使用．
- `FlightSettingController`：`FlightSetting`のCanvas表示/非表示．
- `SettingController`：`Setting`（未使用）のCanvas表示/非表示．
- `ModelInstantiator`：飛行機を`Resources/`から実体化．飛行機はこれにより出現する．

### 独立して動くclassたち
以下の`class`は`MonoBehaviour`を継承せず，属性によりシーンがロードされる前に初期化される．
- `Config`：`Config.txt`の監視と値の保持
- `AircraftData`：`AircraftData/`ディレクトリの監視と機体設計値の保持
- `UIBase`：`UIManager`で管理する`UIClasses`を使うための基底`class`
- `SerialHandler`：シリアル通信を管理．ラダー値，長押し時のイベント発火

### UIManager
自身はシングルトンパターンで初期化，以下の`class`のインスタンスを取得します．
- `PreflightScreen`：未使用
- `FlightSettingScreen`：フライト前パラメーター設定画面
- `ResultScreen`：結果表示画面

### GameManager
（`GameManager`を見れば，ゲームのおおまかな仕組みがわかるようにしたかった）  
自身はシングルトンパターンで初期化，以下の`class`のコンストラクタを実行し，インスタンスを取得します．
- `GameParameters`：ゲーム進行に関わるフラグや変数の保持
- `AerodynamicParameters`：空力計算用変数の保持
- `AerodynamicCalculator`；空力計算処理
- `PilotPositionSensor`：パイロット重心位置のリセット
- `HoldingDetector`：長押し時の処理（`CameraManager`をインスタンス化と同時に取得，`SerialHandler`に関数をイベントとして登録）

## シーンが再ロードされたとき
基本的に全ての`GameObject`が一度破棄され，付随するスクリプトとともに再度初期化されます．
### UIManager
シングルトンパターンのため破棄されません．  
しかしながら`Start()`関数は再び実行されるため，問題なく再生成された`Canvas`を取得できます．
### GameManager
同様に破棄されません．  
`Start()`関数内の`AerodynamicCalculator`の`Initialize()`関数は上手く動かなかったので，`sceneLoaded`イベントに登録しました．
- `AerodynamicCalculator`は`Aircraft`の`RigidBody`を持っている必要がありますが，シーンがロードされるたびにこれは破棄されてしまう問題がありました（存在しないものを参照してしまう`NullReferenceException`が発生しました）．

## GameParameters.Status.Preperation
### GameManager
`Update()`にある通り，`GameParameters.Status.Preperation`である限りは`Time.timeScale = 0f;`が設定され続け，時間が止まったままになります．  
パイロット重心センサーの更新処理は止めていないので，フライト前に動作を確認することができるようになっています．
> [!TIP]
> `Time.timeScale = 0f;`のとき，`FixedUpdate()`も止まっています！要注意！
### UIManager
`RefleshScreen()`でUIオブジェクトの破棄と再生成をおこないます．  
`FlightSetting`に対してはオブジェクトを追加する形です．

## GameParameters.Status.Flightへの移行
### 移行のトリガー
- `FlightSettingCloseButton`：ボタンのクリックの検出
- `FlightSettingController`：`StartButton`（`InputManager`に設定されている）の押下の検出
- `HoldingDetector`：ラダーの長押し

### GameManager
`Time.timeScale = 1f;`に更新され，時間が動き出します．
`FixedUpdate()`内の`CalculatorFixedUpdate();`が実行されるようになります．

### UIManager
`RefleshScreen()`により`Canvas`が非表示になります．

### AeroDynamicCalculator
以下の文により，飛行機に力が加わり，挙動を変化させます．
```csharp
aero.PlaneRigidbody.AddRelativeForce(AerodynamicForce, ForceMode.Force);
aero.PlaneRigidbody.AddRelativeTorque(AerodynamicMomentum, ForceMode.Force);
aero.PlaneRigidbody.AddForce(TakeoffForce, ForceMode.Force);
```
可変慣性モーメントは，`CalculatorFixedUpdate()`内で`Config.EnableDynamicPitchInertia == true`のとき動作  
- 初期化済フラグが立っていなければ，`DynamicPitchInertiaInitialize()`により初期化
- `DynamicPitchInertia()`で毎フレーム計算

## GameParameters.Status.Splashdownへの移行 
### 移行のトリガー
- `prohibitedArea`：衝突イベント`OnCollisionEnter()`
- `Splashdown`：衝突イベント`OnCollisionEnter()`

### UIManager
`ResultScreen`により結果画面を生成し，ページ送りはボタンによってできるように関数が設定してあり，ページは`enum`で保持しています．
  
## Gameparameters.Status.Preperationへの移行（シーンの再ロード）
### シーンの再ロード方法
```csharp
SceneManager.LoadScene("FlightScene"); // ①名前で指定
SceneManager.LoadScene(SceneManager.GetActiveScene().name); // ②現在のシーンの名前を取得して指定
```

### 移行のトリガー
- `LoadSceneController`：`ResetButton`（`InputManager`に設定されている）の押下の検出
- `HoldingDetector`：ラダーの長押し
