# Gitについて

## Git管理で複数人開発を進めやすくするポイント
- できるだけC#スクリプトで完結させる．
  - GitはUnityプロジェクト自体（バイナリファイル）の管理は得意じゃない、テキストファイルが一番．
  - 複雑にアタッチしたりしないこと．外れたら何もわからなくなる．
- 機能を追加する場合は何かに複雑に書き足すより、新しく作る．
- コメントはたくさんつける．
- なるべくコンフリクトしないように，スクリプトの変更範囲などを共有しておく．

Gitで悩みたくないなら，
- 自分のブランチを自分の作業のバックアップとして使ってください．
- `main`ブランチにマージしなくてもいいです．
- 誰か一人が`main`ブランチを触るようにしたほうがいい可能性もあります．
  - 他の人の変更を取り入れたいときはコピーするとか，Discordで送るとか，原始的な方法もありです．

## 注意点
### GitHub LFS
50MB以上のファイルは警告が出て，100MB以上のファイルは`push`することができません．
間違えてコミットしてしまった場合は，`git reset --soft`を実行し，コミットだけを取り消す必要があります．

### コミットするとき
***必ずUnityを閉じてください***

ファイルが破損する原因になるかもしれません．

### .gitignoreや.gitattribute
Gitで管理しないファイルやディレクトリを指定する`.gitignore`と，Gitがどのようにファイルを扱うかを指定する`.gitattribute`は見直してほしいです．  
現状不十分かもしれません．
- 参考になりそうなサイト
  - <https://cbagames.jp/2025/03/14/unity-git-management-guide/>

## ソフトが動かなくなって，どうしようもなくなったら
`--hard`オプションを付けて`git reset`を実行することで，変更内容が取り消され，指定のコミットの状態に強制的に合わせることができます．  
かなり強引な操作なので，気をつけて実行してください．
1. 新しく作った，残しておきたいスクリプトを`Desktop/`などのどこか安全な場所に避難させる．
2. 直前のコミットに戻すなら
  ```git
  git reset --hard HEAD^
  ```
3. 現在のリモート（`origin/main`）にあわせるなら
  ```git
  git reset --hard origin/main
  ```
