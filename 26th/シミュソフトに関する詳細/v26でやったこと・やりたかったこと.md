## やりたかったこと

### `GameManager.cs`による包括的ゲーム進行


目的：<br>
処理の流れを明確にするため．

概要：<br>
`GameManager.cs`に以下のようなロジックを組み込む．
全てのスクリプトに含まれるクラスのインスタンスを持ち，全ての処理はここを起点に開始する．
```mermaid
flowchart TD

subgraph Start
    inputSpec["機体データ読み込み"]
    inputObj["GameObject取得"]
    aero["AeroDynamicCalculator初期化"]

    inputSpec --> inputObj --> aero
end

subgraph Update
    drawUI["UI描写"]
    button["ボタンの処理"]
    updateConf["Config更新"]
    drawUI --> button --> updateConf
end

subgraph FixedUpdate
direction TB
    inputFlag["フラグ取得"]
    ifstart{"フライト開始?"}
    ifLand{"着水?"}
    calc["空力計算"]
    result["結果表示"]
    inputFlag --> ifstart
    ifstart -- "YES" --> ifLand
    ifLand -- "YES" --> result
    ifLand --"NO" --> calc
end

Start ~~~ Update ~~~ FixedUpdate
```

現状：<br>
- 以下のクラスをインスタンス化している
  - ゲーム進行に関わる変数を持つクラス`GameParameters`
  - 空力計算に関わる変数を持つクラス`AeroDynamicParameters`
  - 空力計算処理を行うクラス`AeroDynamicCalculator`
  - パイロットの定常位置を確定するクラス`PilotPositionSensor`
  - ラダーの長押しを判定するクラス`HoldingDetector`
- `CameraManeger`をコンポーネントとして取得
- `GameParameters.Status`に基づいて時間を進行／停止
- `FixedUpdate`で`AeroDynamicCalculator.CalculatorFixedUpdate()`を毎フレーム実行

懸念点：<br>
- 1つのゲームオブジェクトに対して1つのスクリプトを――というUnityの良さ(?)を台無しにする．
- 逆にわかりにくくなる可能性．
- C#スクリプト内でインスタンス化する場合，`MonoBehavior`を継承できなくなり，Unityのゲームオブジェクトにアタッチできなくなる（`using UnityEngine;`はできるので，ゲームオブジェクトの制御はできる）．
